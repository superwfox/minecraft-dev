# 快速开始

跟着这篇走，五分钟做出你的第一个插件。**全程不用写代码、不用装任何环境**，一个浏览器就够了。

## 准备：打开平台并登录

1. 浏览器访问：[https://minecraft-dev-platform.pages.dev](https://minecraft-dev-platform.pages.dev)
2. 点右上角 **「登录」**，用 GitHub 账号授权（没有就顺手注册一个，免费）。
3. 登录后鼠标移到右上角头像，能看到 **剩余额度**。

> **关于额度**：平台已取消每月免费额度。原有充值余额继续保留；未配置自己的 Key 时，可继续使用充值余额走平台模型（1 元 = 1 件，¥25 得银徽、¥50 得金徽）。
>
> **推荐 · 自带 DeepSeek Key（所有用户可用）**：在 Key 弹窗中填入自己的 [DeepSeek API Key](https://platform.deepseek.com/)。Key 只保存在当前浏览器；所有模型请求仍使用统一服务端模型路由，Key 只随对应请求临时传递，不写入任务状态或数据库，并跳过平台模型计费；构建次数上限仍然有效。

## 第一步：描述你的需求

进入对话页，在输入框里用**大白话**说清楚你想要什么插件。

### 示例

```
请帮我做一个玩家进服后被踢出、并提示正在维护的插件，
另外支持用 /setNotice 命令设置踢出时的提示文字
```

### 怎么描述才能做得准？

一句话原则：**把「什么时候、做什么、能不能配置」说清楚。**

| 👍 这样说（清楚） | 👎 别这样说（太空） |
| --- | --- |
| 玩家**进服时**发送欢迎消息 | 做个好用的插件 |
| 玩家**右键告示牌时**传送到出生点 | 实现传送功能 |
| 支持用**命令**修改欢迎语 | 可以配置 |
| **只有 OP** 能用 /reload | 加点权限 |

> 想做的功能多，就一条条列出来；越具体，AI 越不容易跑偏。

<!-- 截图：输入框填好示例需求 -->

## 第二步：选核心和版本

发送需求后，AI 会让你选 **服务端核心** 和 **MC 版本**。

- **核心**：不确定就选 **Paper**（性能好、API 全，主流服务器都用它）。
- **版本**：不确定就选一个**主流稳定版**（如 1.21 / 26.2）。

> 选错也不致命，按你服务器实际跑的版本选最稳。

<!-- 截图：核心与版本选择 -->

## 第三步：回答澄清问题（按需）

需求如果有歧义，AI 会弹出几个**小问题**让你勾选（比如：消息存哪、谁能改、要不要权限）。

- 照着选就行，看不懂的选默认项即可。
- 旁边会实时滚动 AI 的思考过程，**不用管它，等就好**。

需求够清楚时，这一步会直接跳过。

## 第四步：确认行为路径结构

澄清后，模型会构建行为路径结构树。Main 下每列是一条需求路径，每个步骤绑定实现文件；点击节点原位查看细节，在底部输入自然语言修正，满意后确认结构并开始生成。

- 多条路径展示同一需求的不同触发方式或业务过程，不需要手动勾选。
- 需要调整时，在底部输入修正意见，由模型更新相关步骤、文件与契约。
- 核对完成后，点击“确认结构并开始生成”。

> 点击节点可以原位查看实现文件与 Node contract。

## 第五步：等它生成 + 构建

确认结构后，页面显示逐文件生成与检查进度：

| 阶段 | 大概耗时 | 它在干嘛 |
| --- | --- | --- |
| 规划 | 20–40 秒 | AI 想清楚要建哪些文件、怎么分工 |
| 生成 | 1–2 分钟 | 并发写出 Java 代码 + plugin.yml + 配置 + pom.xml，并自查 |
| 校验 | 随路径数量与模型响应变化 | 检查文件完整性、契约与需求路径的实际代码 |
| 构建 | 2–3 分钟 | 云端 Maven 编译打包；编译报错会自动修了重打 |

耗时取决于文件、路径数量和模型、构建响应。刷新或中断后，使用“继续任务”恢复保存的进度。

## 第六步：下载并安装到服务器

1. 完成后点 **「下载 JAR」**，得到一个压缩包，解压拿到 `.jar` 文件。
2. 把 `.jar` 丢进服务器的 **`plugins/`** 目录。
3. 重启服务器（或 `/reload confirm`），插件自动加载。
4. 进游戏测试效果。

> 可以同时下载 Maven 源码 ZIP 和 PROJECT_TREE.md。路径实线表示静态审查与对应代码编译通过，游戏内效果仍需自行实测。

## 常见问题

**Q：生成失败 / 卡住了？**
先刷新重试一次。若仍失败，多半是需求太复杂或描述太模糊——**拆成更简单的需求**分次做，或进群把情况发给作者。

**Q：做出来的插件不对劲？**
用「重新生成」在原需求上**追加说明**（例如「欢迎消息要带玩家名」），比从头重写更准。

**Q：哪些插件适合用它做？**
✅ 适合：进服/退服/聊天/破坏方块等**事件监听**、传送/给物品等**简单命令**、**配置读写**、**定时任务**、**权限判断**。
⚠️ 暂不擅长：复杂经济系统、RPG（技能/职业/属性）、小游戏、数据库（MySQL 等）集成。这类建议先用它出个框架，再找人完善。

**Q：额度怎么算、不够用了怎么办？**
每月免费额度已取消；原有充值余额不会清零，也可继续在「充值额度」中增加余额（1 元 = 1 件）。
所有用户都可以填写自己的 [DeepSeek API Key](https://platform.deepseek.com/)，使用自己的模型额度且不扣平台余额。Key 保存在当前浏览器；需要服务端编排的生成请求会临时携带 Key，但服务端不会将它写入任务状态或数据库。

**Q：生成的代码安全吗？**
代码由 AI 生成并经自动审查，不含后门；上生产前建议自己测一下。
