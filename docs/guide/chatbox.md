# 对话框

踏海的所有操作都从对话页中间的对话框开始。你不需要先填表单或选择模板，把想要的插件写进对话框发送即可；需要补充的信息，平台会在发送后再问。

输入框会随内容自动增高，最高使用网页可视高度扣除页面上下留白后的 75%；超过后在框内滚动，底部操作按钮保持可见。

## 可以输入什么

### 普通文字

用大白话描述插件要做什么。写清楚**什么时候触发、做什么、能不能配置**，效果最好：

```
玩家进服后被踢出并提示正在维护，
另外支持用 /setNotice 命令修改踢出时的提示文字
```

服务端核心和 MC 版本可以直接写在描述里，例如“Paper 1.21.4”。没写的话，发送后会弹出选择框让你补上。

### Markdown

对话框支持边写边排版，适合功能较多的需求：

| 写法 | 效果 |
| --- | --- |
| `# 标题` | 标题，用来分隔不同功能 |
| `- 内容`、`1. 内容` | 无序列表、有序列表 |
| `**文字**` | 加粗 |
| `` `文字` `` | 行内代码，适合写命令、权限节点、配置键 |

| 按键 | 作用 |
| --- | --- |
| Enter | 只有一段普通文字时直接发送；内容里有多段、列表、标题或代码时换段 |
| Shift + Enter | 段内换行 |
| Ctrl + Enter（macOS 为 ⌘ + Enter） | 任何时候都直接发送 |

### 代码块

输入三个反引号加语言名（例如 ` ```yaml `）后按 Enter，开始写代码；写完后另起一行输入结尾的三个反引号，这段内容就会变成代码块。适合贴上期望的配置格式、示例命令输出，或者一段想参考的 Java 代码：

````
```yaml
cooldown: 5
max-homes: 3
```
````

光标在代码块末尾的空行时再按一次 Enter，即可离开代码块继续写文字。

### JAR 文件

点击对话框角落的 **+**，或者直接把 `.jar` 文件拖进对话框，就能把现有插件导入成可修改的工程。详见[导入 JAR](/features/jar-import)。

### 图片

生成用的对话框目前不接收图片。需要配截图说明实际效果时，在编译结束或失败后打开[问题反馈](/features/feedback)，在同一个输入框里粘贴或拖入 PNG、JPEG、WebP。

## 一键润色

登录后，输入停顿约 3 秒，平台会在后台把你的描述整理成条理更清楚的需求，按钮显示「整理中」。整理完成后出现「应用格式」按钮：

- 点击「应用格式」，用整理后的版本替换输入框内容；
- 不满意可以点旁边的撤销按钮，恢复原来的输入；
- 不点就什么都不会改变，直接发送原文也可以。

需求已经写得很清楚，或者包含大段代码时，可以不用润色。

## 对话框旁的按钮

| 按钮 | 作用 |
| --- | --- |
| + | 导入 JAR |
| 技能 | 展开技能栏，挂载额外能力，见[技能库](/features/skills) |
| 提示词历史 | 搜索以前发过的需求，可以复制提示词、恢复任务或删除记录，见[工程历史](/features/project-history) |

## 发送之后

1. **完整性检查**：描述缺少关键内容时（例如没说清玩家怎么触发），对话框下方会列出“还需要补充”的要点，补充后继续。
2. **核心与版本**：描述里没有写明时，弹出选择框。不确定就选 Paper 和服务器实际运行的版本。
3. **确认问题**：需求有歧义时，以卡片形式让你选择，例如数据用 YAML 还是 PDC 保存。看不懂的选默认项即可。
4. **结构树**：确认需求后进入[结构树](/features/structure-tree)。

处理过程中按 **Esc** 可以撤回当前请求，已经消耗的 token 会照常结算。
