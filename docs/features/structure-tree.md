# 结构树与行为路径

生成代码之前，模型先把你的需求拆成一棵结构树。你在这里确认插件“会做哪些事、每件事分几步、由哪些文件实现”，确认后才开始写代码。

## 怎么读结构树

- **顶部长卡片**是插件主类（Main），负责注册命令、监听器和启动服务。
- **下面每一列**是一条行为路径，从触发到结果，例如“玩家右键地面圈选领地”“用命令指定坐标圈选领地”。
- **路径上的每个节点**是一个业务步骤，绑定一个或多个要写的文件。不同路径可以共用同一个文件，例如两种圈选方式最后都调用同一个结算逻辑，这个文件只会生成一次。

点击节点会在原地展开详情：这一步负责什么、绑定哪些文件、依赖谁，以及文件对外提供的方法（Node contract）。生成开始后，这里还会显示源码和检查状态。

## 怎么修改

不需要手动勾选或拖动节点。在底部输入框用一句话描述修改，点击「开始修改」，模型会自己找到要改的路径、文件和约定，例如：

- “返回家园增加 5 秒冷却”
- “去掉进服提示，改成用命令查看”
- “圈选领地时最多 100×100 格”

修改可以来回多次。满意后点击「确认结构并开始生成」，结构就会锁定。

## 虚线和实线

| 显示 | 含义 |
| --- | --- |
| 虚线 | 这条路径还没有通过检查，或者代码改动后需要重新检查 |
| 粒子动画后变成实线 | 这条路径的静态检查和**同一版本代码**的编译都已通过 |

结构图左右还有内容时，边缘会亮起金色的线灯，提示可以横向滚动。

实线只代表代码层面检查通过，不代表游戏内测试过。自动修复改动了代码后，旧结论会作废，路径会重新检查。
