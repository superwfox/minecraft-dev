# 问题反馈

生成失败，或者插件在游戏里的表现和预期不一样，可以直接在平台里发布反馈。资料会整理成一个公开的 GitHub Issue，作者在那里回复和跟进修复。

## 两种反馈

| 场景 | 怎么打开 | 需要填什么 |
| --- | --- | --- |
| 这次执行没有完成 | 最终失败时自动弹出一次 | 什么都不用填，报错和执行记录会自动附上；可以补充说明 |
| 实现与预期不符 | 编译成功后，点击 Debug 旁边的「反馈」 | 写下预期和实际表现，可以选择相关的路径和节点 |

## 填写反馈

- 只有一个输入框，支持 Markdown 和换行。截图可以直接粘贴或拖进去，最多 5 张，每张不超过 5 MiB。
- 「相关路径」和「相关节点」可以把问题定位到结构树上的具体位置，对应的文件信息会自动附上。
- 草稿会自动保存，关掉页面也不会丢。

## 发布前确认

点击「发布反馈」后，会先弹出确认窗口，列出即将公开的全部内容：

- 反馈正文和图片；
- **源码 ZIP**：当前工程的源码、资源和 `PROJECT_TREE.md`；
- **诊断包**：需求、模型调用记录和构建日志，用来复现问题。

只有点击「确认公开并发布」才会真正提交，点「返回修改」不会发出任何东西。

::: warning 公开范围
反馈会发布到公开仓库 [superwfox/minecraft-dev](https://github.com/superwfox/minecraft-dev)，所有人都能看到并长期保留。删除 Issue 不会清除 Git 历史中的附件。密钥等凭据会在服务端自动去除，但请不要在正文里写入隐私信息。
:::

## 发布之后

- Issue 会 @ 你当前登录的 GitHub 账号，回复通知遵循你的 GitHub 设置。
- 网络中断导致不确定是否发布成功时，重试会复用同一份资料，不会重复创建 Issue。
- 发布完成后，可以再写一条新的反馈。
