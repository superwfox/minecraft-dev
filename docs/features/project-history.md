# 工程历史

每次生成或导入都会成为一个“工程”，保存在你当前的浏览器里。你可以随时恢复现场、继续未完成的任务、在原工程上追加修改，或者下载以前的版本。

## 保存了什么

- 需求、确认结果、结构树和当前进度；
- 每个版本的源码、资源和构建出的 JAR；
- 输入框和反馈表单的草稿。

工程按 GitHub 账号分开保存。相同的需求提交两次，会保存成两个独立的工程。

::: warning 注意
工程保存在浏览器本地（IndexedDB）。换浏览器、换电脑，或者清理站点数据后，这些工程就看不到了。重要的工程请下载源码 ZIP 备份。
:::

## 恢复与继续

在对话页打开历史记录，可以按关键词搜索。鼠标移到某条记录上，会出现复制、恢复和删除按钮。

- **恢复**只会还原页面现场，不会自动调用模型。进行中的任务会显示为中断，点击「继续任务」后才会接着执行。
- 服务端任务过期后也能恢复：平台会根据本地保存的源码重新建立任务，已经完成的文件会保留，需要重新检查和编译。
- 旧版本留下的、只有提示词的记录只能复制提示词。

## 追加修改

编译完成后，在同一个工程里直接输入新需求，例如“欢迎消息要带玩家名”。平台会：

1. 更新结构树，并列出这次会新增、修改和删除的文件，等你确认；
2. 只修改受影响的文件，其他文件原样保留；
3. 重新检查和编译，生成一个新版本。

新版本失败时，不会覆盖旧版本的源码和 JAR。

## 下载历史版本

每个版本都可以单独下载源码和 JAR。JAR 第一次下载后会缓存在浏览器里，之后即使服务端的构建产物已经过期，也能直接从本地下载。

## 删除工程

删除会清理这个工程在浏览器里的全部数据，并尝试取消服务端还在进行的构建或导入。已经公开发布的反馈不会因此删除。
