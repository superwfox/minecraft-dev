# AI 多阶段工作流

生成围绕同一份结构数据进行：需求确认 → 行为路径规划与确认 → 按依赖生成文件 → 契约核对与模型审查 → 按需求路径静态审查 → 云端编译与修复 → 下载 JAR 和源码。

## 需求与结构确认

前端先预检需求并提取服务端核心、版本，使用 `POST /api/generate/task` 创建任务。Clarifier 最多进行 5 轮澄清，只询问会改变产品行为的关键决策。

结构规划使用 `POST /api/generate/tree`。每个请求只执行一轮模型调用，前端按结果继续、推进 Learning 或等待用户确认。模型调用树工具，不以正文 JSON 替代结构操作：

| 工具 | 用途 |
| --- | --- |
| set_project | 设置项目名、摘要和外部依赖 |
| upsert_module | 维护 Java 子包与业务职责 |
| upsert_node | 维护单个实现文件、依赖和 Node contract |
| upsert_path | 编排行为路径与步骤，绑定已有文件 |
| remove_path | 删除行为路径 |
| remove_items | 删除文件或模块并清理引用 |
| merge_nodes | 合并文件并重写依赖、配对和步骤绑定 |
| finish_tree | 提交结构完整性校验 |

Main 横跨顶部，下面每列是一条从触发到结果的行为路径；步骤绑定一个或多个文件，多条路径可以复用相同文件。实际文件仍按 Java 子包组织。用户通过底部自然语言输入修正，由模型定位范围；点击节点原位查看职责、绑定文件、依赖、契约和源码。

确认时核对修订号并锁定结构，按依赖拓扑派生文件计划、分桶和 Main 装配蓝图，Main 单独位于最后一个生成桶。锁定后只允许受限的审查补缺追加。

## 生成、检查与补缺

Generator 按文件类型工作，输入包含已确认需求、路径步骤、文件职责、依赖契约、Skill 和可用的公共技术知识。同一文件不会因为被多条路径复用而重复生成。

每个文件按生成、审查、返工等持久化阶段推进，每次请求每个目标最多一次模型调用。确定性契约检查先核对包名、类名、公开成员、事件、命令、Main 注册和资源；失败时进入有限返工。单文件最多 3 次返工，动态补缺每个目标最多 3 个类；达到上限的当前版本不被冒充为审查通过。

追加文件使用稳定 nodeId 和统一路径推导，推送 tree_patch 并补入计划。verify 按树核对文件完整性，缺失文件加入修补桶。源码按需从 source 接口加载，浏览器快照不存文件正文。

## 路径验证

路径验证是代码检查，不包含游戏内模拟。文件齐全后，verify 为当前代码指纹安排路径审查桶；bucket 每次只审查一条尚未检查的路径，并沿用计费、取消和 Learning 续接。

模型沿需求步骤检查入口注册、触发条件、调用参数和返回值、条件分支、共享状态、资源、调度、生命周期清理及结果，必须读取关联文件的完整实现。结果逐步保存证据或问题，同时再次核对关联文件契约。

静态结论绑定代码指纹。构建由独立 GitHub Actions 仓执行 Maven；状态接口把真实构建结果绑定到提交与相同代码指纹。某条路径的静态审查和对应编译均通过后，前端播放方块粒子，再把连接线改成实线。

编译修复改变代码后，旧检查立即失效，新版本在重新提交构建前再次按路径审查。路径审查失败会保留原因和虚线；编译成功不覆盖静态失败，也不证明游戏内行为正确，用户仍需进服实测。

## 工具活动与恢复

Skill 上下文、树工具、Learning、路径审查、编译启动和状态刷新使用真实开始与结果事件驱动状态卡动画。连续活动按开始顺序展示，中间仅交叉淡入淡出；最后一项才翻转收拢。编译启动确认不等于编译通过。

树规划使用请求 ID、输入哈希、租约与原子计费，完成请求可重放。刷新后任务进入中断态，由用户手动继续；正式页面从服务端恢复树、检查结论、文件状态和桶位置。独立预览使用独立快照键，避免覆盖正式任务。

## 下载与平台约束

- JAR 由构建产物下载接口提供；下载后任务继续保留至过期。
- 源码 ZIP 在浏览器用已有 JSZip 打包，含 Maven 目录、源码、资源和 PROJECT_TREE.md。文件齐全即可下载，文档如实记录各项检查状态。
- Pages Functions 负责模型和构建编排，Java 编译交给 GitHub Actions，游戏内实测交给用户。
- 树规划每请求一轮，生成和路径审查按持久化阶段分请求推进；状态整体写入，不按节点逐条写库，不新增生产依赖。

旧的分级、流程图、路径选择及 Planner 实现保存在仓库 `.deprecated/flowchart-planner/`，旧 plan、grade、file 接口统一返回 410。
