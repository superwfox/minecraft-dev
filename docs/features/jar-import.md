# 导入 JAR

手上已有一个插件 JAR，想改一点功能或修一个问题？可以把它导入成可修改的工程，再像普通生成一样用自然语言提需求。

## 怎么导入

1. 点击[对话框](/guide/chatbox)角落的 **+**，或者直接把 JAR 拖进对话框。每次只能导入一个 JAR。
2. 选择服务端类型，填写目标版本（例如 1.21.8）。
3. 弹窗会显示执行仓库是公开还是私有。仓库公开时，原始 JAR 和还原出的源码会公开可见，必须勾选同意后才能上传。
4. 点击「开始解析」。

## 导入后会发生什么

1. 云端反编译 JAR，还原 Java 源码、配置文件和资源，并尝试按原样编译一次。
2. 模型阅读还原出的实际源码，分析出结构树。原来的主类名、配置和图片等资源都会保留。
3. 你在结构树上确认后，输入修改需求，后续流程和[追加修改](/features/project-history#追加修改)一样：只改受影响的文件，再检查和编译。

即使原样编译失败，例如原插件依赖了找不到的第三方库，源码和失败原因也会保留。你可以在修改需求里说明怎么处理，例如“去掉对 XX 插件的依赖”。

导入报告会随源码 ZIP 一起下载，记录了原始 JAR 的校验值和还原过程。

## 限制

- 原始 JAR 最大 20 MiB，解压后总量最大 100 MiB，最多 2000 个文件。
- 适合普通 Java 编写的 Paper/Spigot 插件。混淆过的插件、Kotlin 等其他 JVM 语言写的插件，或使用特殊加载方式的插件，不保证能还原。
- 重新打包后，原 JAR 的签名会失效。
- 云端只做反编译和编译，不会运行插件或其中的脚本。
